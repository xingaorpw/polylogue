一个像聊天软件的 AI 工作台：**通讯录里放着 Claude、GPT、Gemini、Grok、DeepSeek，
想单聊就单聊，想拉群就拉群。**

你在做一件事，想让几个模型一起看：一个挑毛病，一个出方案，一个去查漏。
但它们在不同的网页、不同的 App 里，你得手动把 A 的回答复制给 B，再把 B 的
回答复制回来。三轮之后你自己都不知道在讨论什么了。

polylogue 把它们放进一个通讯录：单聊就是单聊，群聊里模型之间可以 `@名字` 直接
接话，你只管说你的问题，剩下的它们自己交接。历史存在本地，能搜、能改名、能导出。

## 安装

```bash
pip install -e .
```

零依赖，只用标准库。Python 3.9+。

## 用法

### 第一次打开：填一次 key，之后不用管

```bash
polylogue --app
```

弹出一个**独立窗口**（不是浏览器标签页），任务栏上有自己的图标，关掉窗口即退出。

第一次打开时，它先看本机有没有现成的 key：

```
┌──────────────────────────────────────────────────┐
│  先接上一个模型                                    │
│                                                  │
│  ✓ 检测到 openrouter 的 key         [就用这个]     │
│    sk-o…a3 · 复用 DSH 凭据                        │
│                                                  │
│  API key  [OpenRouter ▾] [粘贴 key            ]   │
│                                      [ 开始 ]     │
└──────────────────────────────────────────────────┘
```

- 本机已经有 key（OpenRouter / OpenAI / Claude / Gemini / DeepSeek / Grok）→ 点一下「就用这个」
- 没有 → 粘贴一个。存到 `~/.polylogue/config.json`，权限 `600`，不外传

**为什么要一个 key**：程序没法凭空造出模型访问权。能省的是「找 key、配环境变量、
改配置、重启」这些步骤，不是「获得 key」本身。

### 打开就是通讯录，8 个模型已经在里面

不需要配置就能开始聊 —— 装好就有一个按厂商分好类的通讯录，每个都带 Q 版头像：

| 分类 | 成员 | 默认模型 |
|---|---|---|
| Anthropic | Claude | `anthropic/claude-haiku-4.5` |
| OpenAI | GPT | `openai/gpt-4o-mini` |
| Google | Gemini | `google/gemini-2.5-flash` |
| xAI | Grok | `x-ai/grok-4.6` |
| 深度求索 | DeepSeek | `deepseek/deepseek-chat` |
| 阿里 | 通义千问 | `qwen/qwen-plus` |
| 月之暗面 | Kimi | `moonshotai/kimi-k2` |
| 智谱 | 智谱 GLM | `z-ai/glm-4.6` |

这些 model id 是拿真 key 在 OpenRouter 上逐个确认存在的 —— 写错一个，
用户第一次点开就报 404。

### 单聊和群聊是同一套东西

- 点通讯录里的某个人 → **单聊**，只有它回答
- 「＋ 新对话」勾多个人 → **群聊**，它们互相 `@` 接话
- 同一个模型可以同时出现在多个对话里，历史互不干扰

群聊里：

- 不 `@` 任何人 = 同时问所有成员
- `@名字` = 只说给某个人听
- 模型之间也会互相 `@`，一轮轮推进，直到没人再点名

### 工作台长什么样

```
┌────────────────────────────────────────────────────────────────────┐
│ ● polylogue   ⌕ 搜索对话和历史发言…        ◐主题  ☰成员  ⚙设置    │
├──────────────┬─────────────────────────────────────┬───────────────┤
│  会话 │ 通讯录│  架构评审        ●●●        ⇩ 导出  │ 花费          │
│              ├─────────────────────────────────────┤ tokens  1,234 │
│ ＋ 新对话     │  ● Claude                           │ 成本 $0.0089  │
│              │    这里有个竞态：两个线程同时写配置  │               │
│ ▾ 常用     1 │                                     │ 上下文        │
│   ▣ 架构评审 │                        @Claude 看下… │ ▓▓▓░░░░       │
│              │                                     │ 压缩省下 71%  │
│ ▾ Anthropic  │  ● GPT                              │               │
│   ○ Claude   │    同意，但锁的粒度要再想，别锁整份  │ 成员          │
│ ▾ OpenAI     │                                     │ ● Claude 312  │
│   ○ GPT      │  ● Gemini                           │ ● GPT    198  │
│ ▾ Google     │    改成原子替换：写临时再 rename     │ ● Gemini 245  │
│   ○ Gemini   ├─────────────────────────────────────┤               │
│              │ @Claude @GPT @Gemini      [ 发送 ]   │               │
└──────────────┴─────────────────────────────────────┴───────────────┘
```

- **左栏两个标签**：`会话` 是你的对话，`通讯录` 是模型。两边都按分类折叠
  （QQ 那种分组），分类名可以自己填
- **改名**：点标题，或会话条目上的 ✎
- **搜索**：顶部搜索框，跨所有对话搜标题和每一句发言，命中处高亮并跳到那个对话
- **头像**：每个模型自带一张手绘 Q 版形象（纯 SVG，不联网）；通讯录里点 ▣ 换成
  你自己上传的图（≤900KB，只接受 data URI，不收外链）
- **明暗两套主题**：右上角 ◐ 一键切，存在本地
- 右栏实时显示每个模型的 token 和花费；查不到价格的标「未知」，**不按 0 算**

### 命令行

```bash
# 同时问三个模型（不进工作台，直接打一行）
polylogue -m gemini,grok,deepseek "这个设计有什么问题"

# 只点名一个，让它自己交接
polylogue -m gemini,grok,deepseek "@gemini 先出方案"

# 交互模式
polylogue -m gemini,grok,deepseek

# 只开本地网页（不开独立窗口）
polylogue --web --port 8765
```

启动输出（真实捕获）：

```
polylogue 工作台 → http://127.0.0.1:7520
通讯录：8 个模型（自动（检测到 OpenRouter 凭据））
会话：1 个
价格表版本：2026-11（估算，以各家官网为准）
Ctrl+C 退出
```

没有 key 时**不会启动失败**，而是进引导模式：

```
polylogue 工作台 → http://127.0.0.1:7520
没有检测到可用的 API key —— 打开上面的地址，页面上填一个就能用。
价格表版本：2026-11（估算，以各家官网为准）
```

## 数据存在哪

```
~/.polylogue/
├── config.json              设置、key、通讯录、分类
├── conversations/<id>.json  每个对话一个文件，转录在里面
└── avatars/<id>             你上传的头像
```

一个对话一个文件，是为了搜索时只读需要的那些，而不是把全部历史读进内存；
删一个对话也只动一个文件，不会把别的写坏。所有写入都是「写临时文件再替换」，
进程被杀不会留下半个 JSON。

## 轮次多了 token 会不会爆炸

会。所以做了两级控制。

**第一级**：最近 N 条逐字保留，更早的压成「首句 + `@名字`」。
保留首句是因为结论通常在第一句；保留 `@名字` 是因为它决定交接关系，
丢了对话链就断了。

**第二级**：给上下文设 token 硬上限，压完还超就从最老的开始丢，
并在摘要开头注明「更早的 N 条已省略」——不让模型误以为那就是全部历史。

实测（30 轮 × 3 个模型，每轮约 200 字回复）：

```
未压缩: 302 → 9,060 token   （一路涨，没有上限）
压缩后: 302 → 1,508 token   （撞到 1500 预算就封顶）
30 轮累计节省: 71.2%
```

**压不小就不压**：短发言加上 `[名字]` 前缀和省略号之后，摘要可能比原文还长。
这种情况直接跳过、原样保留 —— 压缩不该是负优化。

不用大模型做摘要，因为那要多花一次调用的钱和延迟，而且它要读的上下文
和原对话一样长，等于没省。

## 报错说人话

不会把 `HTTP 402: {"error":{"message":"This request requires more credits..."}}`
甩给你：

```
openrouter 余额不够：这次请求按 4096 tokens 预留，账户只够 1599。
把 max_tokens 调到 1599 以下，或换「省钱」档 / 充值。
```

覆盖 401（key 无效）、402（余额不够）、404（模型下线）、429（限流）、5xx。

推理模型把预算全花在思考上、正文返回空的时候，也会明确告诉你，而不是
在界面上留一个空气泡。

## 它凭什么比单开一个模型好

### 1. 模型只被点名时才说话

每个模型都能看到全部转录，但**只有被 `@` 到才发言**。没点名的模型认为
事情已经说清楚了，就保持沉默 —— 这既是省钱，也是收敛信号。

### 2. 同一轮并行，互相看不见

一次问多个模型时同时发请求，这一轮里它们看不到彼此的答案。
这样才是独立的第二意见；如果 B 能看到 A 刚说的话，它就只是在附和。

下一轮它们才看到彼此，这时候才是真正的交叉质疑。

### 3. 三层护栏

轮次上限、调用次数上限、成本硬顶。查不到价格的调用按未知计，
已知成本到上限 1/3 就停 —— 因为真实花费只会更高。

## 常用参数

| 参数 | 说明 |
|---|---|
| `-m, --models` | 命令行模式下直接指定成员，逗号分隔 |
| `--app` | 桌面模式：起服务 + 开独立窗口 |
| `--web` | 只开本地网页 |
| `--port` | 端口，默认 8765 |
| `--roles` | 给成员配角色，如 `a=critic,b=builder` |
| `--max-rounds` | 轮次上限，默认 6 |
| `--max-calls` | 调用次数上限，默认 24 |
| `--max-cost` | 成本上限（美元） |
| `--sequential` | 同轮改串行 |
| `--provider NAME=URL` | 自定义 OpenAI 兼容端点 |
| `--list-providers` | 列出 14 个预设 |

## 已知限制

- **一个 key 才能开工**。程序没法凭空造出模型访问权，能省的只是配置步骤。
- **只有 OpenRouter 这条路验证过真实调用**。省钱档和免费档各 3 个模型都真打过；
  直连 Anthropic / Gemini / xAI 官方接口的适配器有单元测试，但**没有用真 key 打过**。
- **免费模型会限流**。实测 14 个 `:free` 模型里 11 个能出内容，其中若干会把
  预算烧在思考上导致正文为空（已识别并报错）。429 是常态，不是 bug。
- **强力档要余额**。免费层账户调 `claude-opus-4.6` 会 402，因为按 4096 tokens
  预留而账户只买得起 1599。
- **成本是估算**。价格表版本 2026-11，数字来自 OpenRouter `/api/v1/models` 的
  pricing 字段，但各家官网会调价；查不到价格的模型按「未知」处理，不当 0。
- **压缩是有损的**。早期发言只剩首句和 `@名字`，细节会丢。需要完整细节时
  把「逐字保留最近几条」调大。
- **前端只做了 DOM + 像素级验证**。开发过程中没有视觉通道 —— 能确认的是
  「渲染出来了、明暗两套真的不一样、头像都加载了」，间距、字号、配色这些
  观感问题得人看一眼。
- **Q 版头像是手写的 SVG，不是官方素材**。用配色和标志性元素区分厂商，
  不是各家的官方形象。
- **搜索是全文顺序扫描**。对话上百个之后会变慢，没有建索引。
- **工作台没有鉴权**。默认只监听 `127.0.0.1`，别改成 `0.0.0.0` 挂公网。
